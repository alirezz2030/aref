# 5 Data Analyst Portfolio Projects

This pack contains five end-to-end project kits built around synthetic data. They are designed to demonstrate business understanding, data cleaning, SQL, Python/pandas, visualization, KPI definition, and recommendations.

## Projects at a glance

| Project | Primary skills | Core deliverable |
|---|---|---|
| 1. Sales and Profitability | KPI design, SQL aggregation, margins, trend analysis | Sales & profitability dashboard |
| 2. E-commerce Funnel and A/B Test | Funnels, conversion rates, confidence intervals, test design | Experiment decision report |
| 3. Customer RFM Segmentation | Customer-level aggregation, segmentation, retention strategy | RFM and marketing dashboard |
| 4. HR Attrition Analysis | Group comparisons, data quality, responsible reporting | Aggregate HR dashboard |
| 5. Inventory and Supply Chain | Fulfillment, stockouts, operational metrics, replenishment | Inventory performance dashboard |

## Folder structure

Each project folder includes:
- `README.md` — business problem, questions, KPIs, workflow, deliverables, and caveats.
- `data/` — synthetic CSV files that can be loaded into Python, SQL, or Power BI.
- `notebooks/` — a runnable analysis notebook with Markdown explanations and commented Python examples.
- `sql/analysis_queries.sql` — example SQLite queries to adapt and extend.

## Recommended order

Start with Sales and Profitability, then E-commerce A/B Testing, Customer RFM, Inventory, and HR Attrition. This order builds from business KPIs toward experimentation, segmentation, operations, and responsible people analytics.

## How to turn a project into a strong portfolio case study

1. Rebuild the analysis yourself instead of only copying the supplied solution.
2. Verify the data grain, definitions, and quality before creating KPIs.
3. Create a Power BI report with a clear executive overview and useful drill-downs.
4. Write a one-page case study with the problem, analysis process, three findings, two recommendations, and limitations.
5. Add screenshots, SQL, notebook, data dictionary, and a clear synthetic-data disclosure to GitHub.
6. Be ready to explain why you chose each metric, how you validated the result, and what additional data you would request in a real project.

**Important:** All records in this pack are synthetic and for learning only. Treat every business result as illustrative. The HR project must be used only for aggregate educational analysis, not for decisions about individuals.
